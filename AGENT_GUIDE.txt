2. 已确认规则
--------------------------------------------------
2.1 基础设定
- 玩家 A / B
- 模式：
  正常：每人 64 枚筹码
  极限：每人 16 枚筹码
- 每人 4 张牌，牌面值：
  A = 1
  2 = 2
  4 = 4
  8 = 8
- 牌位编号：1、2、3、4
- 牌状态：
  暗牌：只看牌背
  明牌：下注阶段可看牌面
- 开局双方各自洗牌
- 每轮不重新洗牌，牌局状态跨轮保留

2.2 最终可见性规则
阶段      自己能看到                              对手能看到          系统额外告知
翻转      不显示任何牌面/牌背/明暗                不显示任何信息      无
易位      不显示任何牌面/牌背/明暗                不显示任何信息      默认公开：对手易位的两个牌号、非法易位记录
下注      自己的牌：明牌显示牌面，暗牌显示牌背    不显示              双方明牌总数之和、底注、投注额
结算      不自动公开双方牌面                      不自动公开          最终比分、胜负、赔付、扣除

实现要求：
- 翻转、易位阶段，服务端不能把任何牌的明暗或点数发给客户端。
- 玩家在这两个阶段是盲选。
- 易位如果选错，服务端返回非法易位，玩家重新选。
- 下注阶段，每个玩家只能看到自己的 4 张牌。
- 下注阶段己方明牌可以看到点数，暗牌只看牌背。
- 系统告知双方明牌总数之和，用于计算底注。
- 结算后只告知结果，不自动翻牌。
- 默认保留原规则：易位阶段公开对手选择的两个牌号和非法记录。
- 如果后面想全隐藏，把 PUBLIC_SWAP_ACTION 设为 false。

2.3 每轮流程
翻转 -> 易位 -> 底注 -> 跟注/加注/停注 -> 结算 -> 下一轮
- 首轮随机决定先手
- 此后每轮交换先后手
- 翻转、易位、下注都是先手先做
- 结算从后手牌堆开始

2.4 翻转 step1
当前玩家选择一个牌位 n：
- 比较对手的 n 号牌与自己的 n 号牌状态
- 状态相同：翻转自己的 n 号牌
- 状态不同：交换双方的 n 号牌
- 玩家不可得知对手选择的牌位 n
- 先手、后手依次完成，然后进入易位

2.5 易位 step2
当前玩家选择两个牌位 i, j：
- 如果这两张牌状态相同：易位生效
- 如果状态不同：
  非法易位
  提示玩家重新选择
  不改变牌局状态
- 默认公开对手易位的两个牌号
- 默认公开所有非法易位记录
- 不可公开对手牌的明暗状态
- 先手、后手依次完成，然后进入下注

2.6 底注
下注开始时：
底注 = ceil(双方明牌总数 / 2)
- 双方各以这个数目作为底注
- 先手先检查筹码
- 先手无力支付：先手输，后手获胜
- 先手能付、后手不能付：后手输，先手获胜
- 双方都不能付：先手先检查，所以后手获胜

2.7 跟注 / 加注 / 停注
从先手开始轮流：
- 跟注：每次 2 枚
- 跟注后，可以决定是否加注
- 加注数量不限
- 自己的总注必须同时满足：
  自己的总注 <= 自己当前筹码数
  自己的总注 <= floor(对方当前筹码数 / 2)
- 非法操作要拒绝
- 停注：
  先手停注后，后手可以再做一次选择，然后自动停注
  后手停注后，直接结算
- 场上总筹码数记为 N

2.8 结算算法
- 每轮 S = 0
- 双方得分从 0 开始
- 从后手牌堆开始
- 依次处理牌位 1 到 4：
  暗牌：跳过，继续当前玩家
  明牌：把牌面值 a 加到 S，S = S mod 5
  如果 S == 0，当前玩家加 1 分
  完成一次明牌计分后，切换到另一方
- 当一方跳过或记录完第 4 号牌后，另一方继续，直到另一方也完成第 4 号牌
- 记录 lastBrightOwner = 最后一张被处理的明牌所属的玩家

2.9 破平规则
如果双方得分相同，包括 0:0 和 1:1 这类非 0 平局：
1. 从 lastBrightOwner 的另一方开始
2. 依次执行：S = (S + 1) mod 5
3. 谁先让 S == 0，谁加 1 分
4. 加完分后结算结束
如果没有任何明牌，理论不会发生；代码兜底从后手开始。

2.10 赔付
设结算后双方得分为 a, b，且按原文：
a > b 时，A 告负，B 获胜
也就是高分者输。
若 b == 0：b = 1
然后：
败方支付 = ceil(N * a / (a + b))
胜方扣除 = ceil(N / (a + b))
胜方实收 = 败方支付 - 胜方扣除
筹码变化：
败方筹码 -= 败方支付
胜方筹码 += 胜方实收
如果败方筹码不够：
- 支付剩余全部筹码
- 游戏立即结束
- 胜方为对方
被扣除的筹码从游戏中移除。

2.11 游戏结束
- 每轮底注阶段检查筹码
- 先手先检查
- 先手不能付：先手输
- 先手能付、后手不能付：后手输
- 双方都不能付：后手获胜
- 赔付时败方筹码不足：支付剩余，游戏结束

2.12 断线重连
- 创建/加入房间时返回：
  roomId: string
  playerToken: string
  seat: 0 | 1
- 前端把 roomId + playerToken + seat 存入 localStorage
- 刷新或断网后，Socket 重连，发送：
  session:resume { roomId, playerToken }
- 服务端恢复座位
- 重新发送当前完整个性化状态
- 房间保留 10 分钟
- 对方掉线时暂停，不自动代打
- 双方都掉线也保留，超时清理

5. 核心数据模型
--------------------------------------------------
type CardValue = 1 | 2 | 4 | 8;

interface Card {
  id: string;
  value: CardValue;
  faceUp: boolean;
}

interface PlayerState {
  id: 0 | 1;
  name: string;
  chips: number;
  board: Card[]; // 长度 4
  connected: boolean;
  socketId?: string;
}

interface GameState {
  mode: "normal" | "extreme";
  round: number;
  initialFirst: 0 | 1;
  first: 0 | 1;
  phase: "flip" | "swap" | "bet" | "settle" | "gameOver";
  turn: 0 | 1;
  players: [PlayerState, PlayerState];

  flip: {
    acted: [boolean, boolean];
  };

  swap: {
    acted: [boolean, boolean];
    attempts: {
      player: 0 | 1;
      slots: [number, number];
      valid: boolean;
    }[];
  };

  bet: {
    ante: number;
    bets: [number, number];
    pot: number;
    firstStopped: boolean;
    finished: boolean;
  };

  settlementResult?: {
    S: number;
    scores: [number, number];
    loser: 0 | 1;
    winner: 0 | 1;
    payment: number;
    deduction: number;
    winnerReceive: number;
  };
}


6. 规则引擎函数
--------------------------------------------------
createGame(mode): GameState
startRound(state): GameState

applyFlip(state, actor, slot): Result
applySwap(state, actor, slotA, slotB): Result
calculateAnte(state): number
applyBet(state, actor, action): Result
runSettlement(state): SettlementResult

checkNextRoundSolvency(state): GameOverResult

getStateForPlayer(state, playerIndex): PlayerView

关键要求：
- applyFlip：同状态翻自己的牌，不同状态交换双方的牌
- applySwap：只允许交换自己牌堆中两张状态相同的牌
- applyBet：校验跟注 2 枚、加注、总注上限、自己筹码上限
- runSettlement：严格实现结算和破平
- getStateForPlayer：过滤隐藏信息


7. Socket 协议
--------------------------------------------------
客户端发服务端：
room:create
room:join
room:ready
room:start
game:action
session:resume
room:leave
game:rematch

服务端发客户端：
room:state
room:error
player:connected
player:disconnected
game:settled
game:over

game:action 载荷：
{ type: "flip", slot: 1 | 2 | 3 | 4 }
{ type: "swap", slots: [1 | 2 | 3 | 4, 1 | 2 | 3 | 4] }
{ type: "bet", action: "call" | "stop", raise?: number }

状态同步要求：
- 每次操作后，服务端给每个玩家发送个性化 room:state
- 翻转、易位阶段：不发送任何牌数据
- 下注阶段：只发送自己的牌
- 结算阶段：只发送结算结果
- 服务端权威，客户端不能自己改状态
